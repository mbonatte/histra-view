# Review of changes after 5bc73cd

Reviewed remote commits 42eb8e0, 5a8ff4a, fa3b6ee and 6023276. Those commits
added tests, documentation and package metadata; they did not change production
solver algorithms. Their successful tests did not establish the claimed
complete mathematical parity.

## Findings and corrections

1. The mapping matrix classified every routine as verified and cited names
   such as `Objects.Interface.CopyCommittedFiberState` that were not real
   declarations in the inspected original source. The corrected
   [inventory and validation register](csharp_python_function_mapping_matrix.md)
   separates a Python AST census from selected native contracts and open work.
2. The new multilinear tests evaluated a helper defined inside the test file
   and ordinary multiplication, without calling a production constitutive law.
   They now exercise real masonry `SpringHysteretic` backbones and the compiled
   evaluator against a newly captured original C# fixture. All previous
   monotonic strain samples are retained and reversals are added. The distinct
   generic plastic law is not implemented; legacy-container numerical calls
   now reject use instead of returning the base class's linear response.
3. A pre-existing numeric material-transfer path replaced the predecessor
   tangent and yield metadata with new-material values. Direct native
   `SpringStateDBclass.SetSpring(false)` calls confirm their restoration. The
   optimized Python path now matches the captured fields for virgin, plastic,
   reversed and repeated-reset cases, including cached-proxy variants.
4. A new runtime-import check exposed a pre-existing all-numeric topology bug:
   the importer returned early when its scalar object list was empty, leaving
   dense arrays uninitialized. It now counts dense rows. Tests check original
   native virgin/restored states and deliberately poison buffers before reimport.

The native fixture captures trial and committed fields, not just final force.
Scalar comparisons require every captured field to be mapped explicitly; the
only transfer exclusions are the named cumulative-energy fields. Python retains
predecessor energy, while native DB restoration omits it. This is a documented,
tested policy difference, not an equality claim. Damage-dependent staged
behavior under that difference remains unqualified.
